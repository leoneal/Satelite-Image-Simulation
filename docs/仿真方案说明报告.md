# 卫星交会成像仿真方案说明报告

> 版本 2.0 | 2026-08-14（v1.0 为 2026-07-17）

---

## 一、项目概述

### 1.1 目标

以观察卫星第一视角对目标卫星进行**空间交会工况**连续成像仿真，生成带有像素级标注的仿真图像数据集，用于**目标检测、实例分割和位姿估计**算法的训练与验证。

### 1.2 技术路线

```
MATLAB 控制 STK → 轨道计算 + 场景构建 → ECI 星历导出 → Blender Cycles 渲染 → 标注生成
```

- **STK 11.6**：高精度轨道力学计算（J2/J4 摄动模型）
- **MATLAB**：通过 COM 接口控制 STK，读取工况数据，导出星历
- **Blender 5.2**：Cycles 物理渲染引擎，2048×2048 分辨率，GPU OptiX 加速
- **Python (Blender API)**：场景构建、批量渲染、标注自动生成

### 1.3 工况数据

**当前使用的工况数据为 `轨道2.xlsx`**（200 Hz 采样，362,401 帧），取代了 v1.0 时期的 34201 行 1 Hz 数据：

| 参数 | 值 |
|------|-----|
| 采样率 | **200 Hz**（帧间 5 ms） |
| 帧数 | 362,401 |
| 距离范围 | **999.9 km → 最近 47.7 km → 999.9 km** |
| 总时长 | 1812 s（约 30 分钟） |
| 数据内容 | 瞬时轨道根数（a/e/i/Ω/ω/ν），a 单位米、角度单位弧度 |

处理流程：`tools/convert_orbit_v2.py` 在 Python 端完成 kepler2cart 转换（与 MATLAB 矩阵公式误差 < 1 m）+ Meeus 天文算法计算太阳位置，输出标准 5-CSV 星历（observer/target/sun/aux + scene_config.json）。

**距离分段渲染策略**（v2.0 数据集）：

| 段 | 帧范围 | 距离 | stride | 帧数 |
|----|--------|------|--------|------|
| 近距段 | 172020–190592 | < 70 km | 131 | 142 |
| 远距段（前） | 136787–172019 | 70–250 km | 1040 | 34 |
| 远距段（后） | 190593–225823 | 70–250 km | 1040 | 34 |

## 三、数据预处理流程

### 3.1 Excel 读取与转换

```
轨道2.xlsx (200Hz, 362401行)
    │
    ▼
convert_orbit_v2.py (Python)
    │  kepler2cart: 精确矩阵公式 R=Rz(-RAAN)·Rx(-inc)·Rz(-argp)
    │  (与MATLAB验证误差 < 1 m)
    │
    ▼
Meeus 太阳位置算法
    │  儒略日 → 太阳黄经/黄纬 → ECI 位置
    │
    ▼
输出 5-CSV 星历 (observer/target/sun/aux + scene_config.json)
```

### 3.2 时间戳生成

原始数据无 UTC 时间戳。按 GEO 平均运动推算采样步长（旧 1Hz 数据为 1 秒/行；新 200Hz 数据为 5 ms/行）。自定义起始历元为 `1 Jul 2026 12:00:00.000 UTC`。

## 四、STK 场景构建

### 4.1 软件交互模式

STK 通过 **COM 启动 + Connect API 操作** 的混合模式与 MATLAB 交互：

```matlab
app = actxserver('STK11.Application');  % COM 启动 STK
conid = stkOpen(stkDefaultHost);       % 打开 Connect 连接
stkInit;                                % 初始化 Connect 命令
% ... 场景操作 ...
```

> **教训：** 纯 TCP Connect 启动不稳定（连接池满、10054 错误），COM 启动后再连接是最稳方案。

### 4.2 卫星加载

两种模式（`config.orbitSource` 控制）：

**手动模式 (`manual`)**：用户指定轨道六根数，用 `stkSetPropClassical` 设置。

**Excel 模式 (`excel`)**：从工况 Excel 载入瞬时根数，转换为 ECI 位置速度后，通过 `stkSetEphemerisCBI` 一键写入 `.e` 文件并加载到 STK（使用 StkExternal propagator）。

### 4.3 传感器与姿态

- 传感器（成像载荷）创建于观察星，FOV 按段配置（v2.0 使用 0.08° 窄视场）
- 姿态设定为观察星始终指向目标卫星（Basic Target 模式）
- **注意：** 本环境 STK Connect 的 `Define`/`SetAttitude` 命令语法报错，传感器 EOIR 配置和 Target Pointing 需在 STK GUI 手动完成

### 4.4 坐标系统

全流程使用 J2000 ECI（地心惯性系）：STK 输出 → CSV → Blender 场景，Z 轴向上，均为右手系，**1:1 直接映射**，无需坐标变换。

### 4.5 场景可视化限制

**已知问题：** `stkNewObj` 创建的卫星在 STK 2D/3D 窗口中**不显示轨道**——原因是 Connect API 不会自动初始化 VO（Visual Object）系统。本环境 `stkExec`（VO/Graphics 命令）不可用，COM 的 `VO.Add()` 参数不兼容。

**影响：** 仅影响 STK 图形显示，不影响数据正确性（`stkPosVelCBI` 验证通过）。

**替代方案：** 在 STK GUI 中手动导入生成的 `.e` 文件查看轨道可视化。

## 五、Blender 渲染管线

### 5.1 场景尺度

Blender 场景统一使用 **km** 为单位（实际米坐标 ×0.001）。相机裁剪面：`clip_start=0.01 km (10m)`，`clip_end=200000 km`。

**浮点精度（关键修复）：** 相机始终置于场景原点，所有物体使用相对坐标（Python float64 计算、Blender float32 存储）。否则 GEO 距离（42164 km）下 float32 精度约 5 m，6.3 m 的卫星几何会彻底扭曲。

### 5.2 星空背景

采用 **相机齐次平面（Camera Backdrop Plane）** 方案：

- 一个发光平面（emission），挂载在相机 z=-100000 km 处（远超任何卫星距离）
- 使用 8K 等矩形星空纹理 + Window 坐标映射
- **天球旋转补偿：** 每帧根据相机姿态计算旋转增量，逆旋转 Mapping 节点使星空固定于 ECI 天球参考系

### 5.3 地球模型

地球为原点处半径 6371 km 球体，材质为 Blue Marble 8K 等矩形纹理 + Principled BSDF。无纹理文件时自动 fallback 为纯蓝色。

### 5.4 卫星模型库（134 颗真实卫星）

**模型来源：** 134 颗卫星 3ds Max 模型（公开几何建模库），分类如下：

| 类别 | 数量 | 命名前缀 |
|------|------|---------|
| 导航卫星 | 7 | NavSat |
| 光学遥感卫星 | 60 | OptSat |
| 微波遥感卫星 | 12 | MicSat |
| 通信卫星 | 55 | ComSat |

**模型转换管线：** 3ds Max MaxScript 批量导出 FBX（保留 mesh 部件分组）→ Blender 导入（unparent → transform bake → 居中 → km 缩放）→ 纹理按 mesh 名字关键词自动匹配 FBX 目录纹理文件（金箔/铝箔/太阳翼板）。

**纹理完备性**（详见 docs/134卫星模型纹理检查报告.md）：

| 状态 | 数量 | 说明 |
|------|------|------|
| 纹理完备 | 39 | UV 100% 覆盖 + ≥2 张纹理 |
| 部分 UV 缺失 | 91 | 部分网格无 UV，fallback 纯色 |
| 无纹理 | 4 | Hubble/SELENE/topex/MEASAT-3，纯色渲染 |

- 微波遥感卫星 12 颗已统一补齐太阳翼纹理（拷贝自导航卫星素材）

**太阳翼自动拆分：** 模型库中左右两翼常合并在同一 mesh（顶点跨 x=0）。管线自动按模型中心 bisect 切成左右两个独立实例；同一翼板的正反面（front/back 共面 mesh）自动归为同一实例。

### 5.5 材质与光照

- 卫星部件使用 **Principled BSDF + Emission 混合材质**（emission 30%，颜色连接纹理），保证深空中微弱光照条件下纹理与部件可见
- 太阳为方向光（Sun Lamp），逐帧更新方向，能量 200
- 去噪和自适应采样已关闭——防止小目标被当作噪声抹除

### 5.6 渲染参数

| 参数 | 值 |
|------|-----|
| 引擎 | Cycles（GPU OptiX，~5-10× 加速） |
| 采样数 | 64 |
| 去噪 / 自适应采样 | 关闭 |
| 分辨率 | 2048×2048 |
| FOV | 0.08°（track 模式） |
| 格式 | 8-bit PNG |

### 5.7 数据扩增

每帧原始图像生成 **15 个扩增变体**：

| 维度 | 参数 | 说明 |
|------|------|------|
| 姿态 | 5 变体（含原始） | 90° 锥形均匀随机扰动四元数，绕随机轴 |
| 光照（角度） | 3 变体（含原始） | 太阳相位角偏移 0° / 60° / 120°（绕相机-目标-太阳平面法线旋转） |
| 光照（强度） | 每组合随机采样 | 太阳能量在 **60–200** 范围内均匀随机（`--sun_energy_range "60,200"`） |

- 扩增姿态扰动同时写入位姿真值（pose 标注），保证标注与图像严格一致
- 姿态与光照强度的随机数均使用**确定性种子**（由帧号+变体号推导）——断点续传后重渲染结果完全一致

### 5.8 点目标数据集生成器

`tools/point_target_generator.py`：解析星历生成**亚像素点目标**数据集（无需 Blender）：

- 目标：高斯 PSF 点扩散模型（FWHM 可配置）
- 背景：幂律分布星场（默认 10,000 颗恒星）
- 输出：灰度 PNG + labels.csv + manifest + train/val 划分

## 六、标注生成管线

### 6.1 部件标注体系（5 类）

| 类别 | ID | 名称 | mesh 命名关键词 |
|------|----|------|----------------|
| 1 | body | 卫星本体 | `body` 开头（或默认归类） |
| 2 | solar_panel | 太阳翼板 | 含 `panel` / `solar` |
| 3 | phased_array_antenna | 相控阵天线 | 含 `phased` / `array` |
| 4 | reflector_antenna | 反射面天线 | 含 `reflector` / `dish` |
| 5 | solar_panel_tripod | 太阳翼支架 | 含 `tripod` / `truss` |

### 6.2 手动标注流程

用户在 Blender GUI 中对每颗卫星进行部件标注（详见 docs/手动标注教程.md）：

1. 导入 FBX，对照模型彩图识别部件
2. 编辑模式按面选择（`Ctrl+L` 选面岛），`P` 分离混合部件
3. 按上表命名关键词重命名部件对象
4. 保存为 `output/blend_files/<卫星名>.blend`

**命名约定**：`<类别前缀><原分类内编号>_<名称>`，如 `导航_1_Beidou-GEO` → `NavSat_1_Beidou-GEO.blend`。渲染循环自动检测 .blend（有则 5 类标注，无则回退 raw FBX 的 body/panel 自动分类）。

### 6.3 实例分割 Mask

采用 **二次渲染** 方案：

1. **Beauty Pass**（核心渲染）：正常材质，得到 RGB 图像
2. **Mask Pass**（1 采样纯色渲染）：将卫星每个部件的材质临时替换为纯色 emission（R 通道编码实例 ID），**同时隐藏星幕与地球**（确保 mask 纯黑背景 + 卫星像素），渲染 1 个采样，从 EXR 读回线性像素值提取 mask
3. **Mask 存储**：8-bit 灰度 PNG，**像素值 ×50 可见编码**（1→50, 2→100, ..., 上限 250），原值 1-5 视觉不可见

### 6.4 COCO 标注

| 任务 | 格式 | 内容 |
|------|------|------|
| 检测 | `coco_detection.json` | bbox (x,y,w,h) + area + category_id |
| 分割 | `coco_segmentation.json` | bbox + area + **RLE 编码** (COCO column-major run-length) |

渲染时直接生成（每子批次一个 JSON，帧号区间命名）；`tools/build_coco.py` 可从磁盘 mask PNG 重建统一 COCO JSON（支持 `--legacy` 解码 v1.0 旧编码）。

### 6.5 其他标注

| 格式 | 内容 |
|------|------|
| YOLO txt | `class_id x_center y_center width height`（归一化）。部件类 0-4；**整星类别 5-15**（每颗卫星一个独立类别，整星 bbox） |
| 位姿 txt | 目标星四元数（含扩增扰动）+ 相对位置：`qx qy qz qw rx ry rz`（ECI 坐标系）|
| **影响因素 CSV** | 每张图像成像条件记录，见 6.6 |
| splits.json | train/val 拆分规则：每 5 帧取 1 帧为验证集 |

**面积过滤：** body/panel ≥ 30 px，天线/支架类 ≥ 2 px（mask 无噪声污染后阈值放宽，保留远距离小天线的标注）。

### 6.6 影响因素标注（factors CSV）

每批渲染输出一个 `annotations/factors_<起帧>_<止帧>.csv`，**每行对应一张图像**，记录该图像的成像条件影响因素：

| 列 | 含义 |
|----|------|
| filename | 图像文件名 |
| frame_id | 原始星历帧号 |
| variation | 扩增变体号（0-14，0 = 原始姿态+原始光照） |
| distance_km | 两星间相对距离（km，3 位小数） |
| sun_phase_angle_deg | 实际光照角度（相机-目标连线与太阳方向的夹角，含相位偏移后的真实值） |
| sun_energy | 太阳光照强度（60–200 随机采样值） |

示例：

```csv
filename,frame_id,variation,distance_km,sun_phase_angle_deg,sun_energy
frame_172020.png,172020,0,69.999,115.84,141.5
frame_172020_v001.png,172020,1,69.999,175.84,99.7
frame_172020_v002.png,172020,2,69.999,124.16,101.4
```

用途：训练/评估时可按距离、光照角度、光照强度做条件分布分析或分组评测。

- 缺失的 COCO 范围由 `tools/build_coco.py` 从 mask PNG 统一重建（含面积过滤，与渲染时标准一致）

## 八、关键踩坑记录

### 8.1 MATLAB 编码

- `.m` 文件必须纯 ASCII（英文注释）——GBK 环境的 MATLAB 无法正确读取 UTF-8 中文
- STK Connect 不接受中文路径——`.e` 文件临时写到 `tempdir`（ASCII）再加载
- `readmatrix` 需 R2019a+；旧版 MATLAB 用 `xlsread` 回退
- `jsonencode` 无 `'PrettyPrint'` 参数；`datetime` 需显式 `'Locale','en_US'`

### 8.2 STK API

- `stkSetPropClassical` 的 a 单位为**米**，角度单位为**弧度**（容易误用 km/deg）
- `stkPosVelCBI('Sun', t)` 不存在——Sun 不是 propagated vehicle（太阳用 Meeus 算法）
- `stkAttitudeCBI` 不可靠——改为几何计算（观察星指向目标 + 目标星对地定向）
- `stkObjNames()` 无参调用

### 8.3 Blender 5.2

- `bpy.ops.object.delete()` 无 `use_confirm` 参数；`bpy.ops.mesh.bisect()` 无 `fill` 参数
- `Material.use_nodes` 已弃用，材质节点需显式 `new()`
- **Track To 约束**在 `-b` 后台模式不生效 → 相机/太阳用旋转矩阵直接构造
- **物体 scale≠1 时 emission 材质不可见** → 用 `size=` 或 `transform_apply(scale=True)`
- **Denoising 抹除小目标** → 必须关闭
- **`Render Result` 渲染两次后 pixels 为空** → mask 用 EXR 写盘回读
- **`bpy.data.libraries.load` 相对路径在 Windows 上解析到盘符根目录** → 必须先 `os.path.abspath`
- **mask PNG 值 ×50 需先转 uint16** → uint8 直接乘会溢出回绕（150×50=7500→76）

### 8.4 标注管线（v2.0 关键修复）

- **Mask 渲染必须隐藏星幕和地球**——否则恒星像素污染 mask 和 COCO 标注
- **FBX 纹理匹配**：emission Color 必须连接到纹理节点（默认白色会洗掉纹理）；`os.listdir` 的目录路径必须 `abspath`（中文相对路径静默失败）
- **3ds Max FBX 导出丢失纹理链接**——纹理改为渲染时按名字关键词匹配 FBX 目录图片

### 8.5 坐标与尺度

- ECI 与 Blender 世界坐标 1:1 映射（均为右手系 Z-up）
- Blender 四元数顺序为 `(w, x, y, z)`，从 STK `(qx, qy, qz, qw)` 取时需注意
- 场景用 km 单位 + 相机置原点避免浮点精度问题

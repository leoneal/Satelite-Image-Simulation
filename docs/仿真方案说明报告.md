# 卫星交会成像仿真方案说明报告

> 版本 1.0 | 2026-07-17

---

## 一、项目概述

### 1.1 目标

以观察卫星第一视角对目标卫星进行**空间交会工况**连续成像仿真，生成带有像素级标注的仿真图像数据集，用于**目标检测、实例分割和位姿估计**算法的训练与验证。

### 1.2 技术路线

```
MATLAB 控制 STK → 轨道计算 + 场景构建 → ECI 星历导出 → Blender Cycles 渲染 → 标注生成
```

- **STK 11.6**：高精度轨道力学计算（J2/J4 摄动模型）
- **MATLAB**：通过 COM 接口控制 STK，读取工况数据，导出星历
- **Blender 5.2**：Cycles 物理渲染引擎，2048×2048 分辨率
- **Python (Blender API)**：场景构建、批量渲染、标注自动生成

### 1.3 工况数据

数据来源为 `orbit_data.xlsx`（34201 行，1秒/行），包含两颗 GEO 卫星在完整交会过程中的瞬时轨道根数（osculating Keplerian elements）：

| 参数 | 单位 | 说明 |
|------|------|------|
| 半长轴 a | 米 | 观测星 38077~42164 km，目标星 ~42164 km |
| 偏心率 e | 无 | 观测星 0→0.154（变轨机动），目标星 ~0 |
| 倾角 i | 弧度 | |
| 升交点赤经 Ω | 弧度 | |
| 近地点幅角 ω | 弧度 | |
| 真近点角 ν | 弧度 | |

**距离剖面：** 16327 km → **最近 47.8 km**（约 6.5 小时后）→ 11198 km，总时长约 9.5 小时。

## 三、数据预处理流程

### 3.1 Excel 读取与转换

```
orbit_data.xlsx
    │
    ▼
loadOrbitExcel.m
    │  readmatrix/xlsread 读取34201×13矩阵
    │
    ▼
逐行 kepler2cart.m
    │  a, e, i, Ω, ω, ν → ECI r(x,y,z), v(vx,vy,vz)
    │
    ▼
连续性检验 + 坏行修复
    │  4行退化数据(e=0时ω不稳定) → 邻行插值
    │  修复后 error < 0.001 km
    │
    ▼
stkSetEphemerisCBI 写.e文件
    │  stk.v.4.0格式, 34201点, EphemerisEciTimePosVel
    │
    ▼
STK 加载 (StkExternal propagator)
```

### 3.2 时间戳生成

原始数据无 UTC 时间戳。根据 Tar_f（目标星真近点角）的增量（7.292e-5 rad/s = GEO 平均运动）推算步长为 **1秒/行**。自定义起始历元为 `1 Jul 2026 12:00:00.000 UTC`。

## 四、STK 场景构建

### 4.1 软件交互模式

STK 通过 **COM 启动 + Connect API 操作** 的混合模式与 MATLAB 交互：

```matlab
app = actxserver('STK11.Application');  % COM 启动 STK
conid = stkOpen(stkDefaultHost);       % 打开 Connect 连接
stkInit;                                % 初始化 Connect 命令
% ... 场景操作 ...
```

> **教训：** 纯 TCP Connect 启动不稳定（连接池满、10054 错误），COM 启动后再连接是最稳方案。

### 4.2 卫星加载

两种模式（`config.orbitSource` 控制）：

**手动模式 (`manual`)**：用户指定轨道六根数，用 `stkSetPropClassical` 设置。

**Excel 模式 (`excel`)**：从 `orbit_data.xlsx` 载入 34201 行瞬时根数，转换为 ECI 位置速度后，通过 `stkSetEphemerisCBI` 一键写入 `.e` 文件并加载到 STK（使用 StkExternal propagator）。

### 4.3 传感器与姿态

- 传感器（成像载荷）创建于观察星，FOV = 0.117°（圆锥半角 0.0585°）
- 姿态设定为观察星始终指向目标卫星（Basic Target 模式）
- **注意：** 本环境 STK Connect 的 `Define`/`SetAttitude` 命令语法报错，传感器 EOIR 配置和 Target Pointing 需在 STK GUI 手动完成

### 4.4 坐标系统

全流程使用 J2000 ECI（地心惯性系）：STK 输出 → CSV → Blender 场景，Z 轴向上，均为右手系，**1:1 直接映射**，无需坐标变换。

### 4.5 场景可视化限制

**已知问题：** `stkNewObj` 创建的卫星在 STK 2D/3D 窗口中**不显示轨道**——原因是 Connect API 不会自动初始化 VO（Visual Object）系统。本环境 `stkExec`（VO/Graphics 命令）不可用，COM 的 `VO.Add()` 参数不兼容。

**影响：** 仅影响 STK 图形显示，不影响数据正确性（`stkPosVelCBI` 验证通过）。

**替代方案：** 在 STK GUI 中手动导入生成的 `.e` 文件查看轨道可视化。

## 五、Blender 渲染管线

### 5.1 场景尺度

Blender 场景统一使用 **km** 为单位（实际米坐标 ×0.001）。相机裁剪面：`clip_start=0.00001 km (10m)`，`clip_end=200000 km`。

### 5.2 星空背景

采用 **相机齐次平面（Camera Backdrop Plane）** 方案：

- 一个发光平面（emission），挂载在相机 z=-100000 km 处（远超任何卫星距离）
- 使用 8K 等矩形星空纹理 + Window 坐标映射
- **天球旋转补偿：** 每帧根据相机姿态计算旋转增量，逆旋转 Mapping 节点使星空固定于 ECI 天球参考系

> **原理：** 相机追踪目标卫星过程中缓慢旋转（GEO 轨道约 7.5°/30min），逆旋转补偿使星空在天球上保持静止。已验证头尾帧差 30 分钟有明显偏移。

### 5.3 地球模型

地球为原点处半径 6371 km 球体，材质为 Blue Marble 8K 等矩形纹理 + Principled BSDF。无纹理文件时自动 fallback 为纯蓝色。

### 5.4 卫星模型

当前使用简易几何体假模型（Blender 基本图形搭建）：

| 部件 | 类别ID | 尺寸 | 说明 |
|------|--------|------|------|
| body | 1 | 4×2×1.5 m³ | 卫星本体 |
| panel_left | 2 | 4×1×0.04 m³ | 左太阳能板 |
| panel_right | 3 | 4×1×0.04 m³ | 右太阳能板 |
| antenna | 4 | r=0.4m, h=0.5m | 天线 |
| thruster | 5 | r=0.3m, h=0.25m | 推进器 |

> **待替换：** 有带部件分组的真实卫星 3D 模型时，替换 `create_satellite_model()` 函数即可，保持部件名称与类别 ID 对应。

### 5.5 材质与光照

- 卫星部件使用 **Principled BSDF + Emission 混合材质**（fac=1.0, 100% emission），确保深空中微弱光照条件下仍可见
- 太阳为方向光（Sun Lamp），逐帧更新方向指向太阳位置
- 去噪和自适应采样已关闭——防止小目标被当作噪声抹除

### 5.6 渲染参数

| 参数 | 值 |
|------|-----|
| 引擎 | Cycles |
| 采样数 | 64（速度优先）/ 128（高质量）|
| 去噪 | 关闭 |
| 自适应采样 | 关闭 |
| 分辨率 | 2048×2048 |
| 格式 | 8-bit PNG |

## 六、标注生成管线

### 6.1 实例分割 Mask

采用 **二次渲染** 方案：

1. **Beauty Pass**（核心渲染）：正常材质，得到 RGB 图像
2. **Mask Pass**（1 采样纯色渲染）：将卫星每个部件的材质临时替换为纯色 emission（R 通道编码类别 ID = 1~5），渲染 1 个采样，从 EXR 读回线性像素值，提取类别 mask
3. **Mask 存储**：使用 zlib/struct 手写 8 位灰度 PNG（像素值 = 类别 ID），绕开 Blender image API 的兼容问题

### 6.2 COCO 标注

| 任务 | 格式 | 内容 |
|------|------|------|
| 检测 | `coco_detection.json` | bbox (x,y,w,h) + area + category_id |
| 分割 | `coco_segmentation.json` | bbox + area + **RLE 编码** (COCO column-major run-length) |

由 `tools/build_coco.py` 从磁盘 mask PNG 重建统一 COCO JSON，支持递归扫描多批次子目录。

### 6.3 其他标注

| 格式 | 内容 |
|------|------|
| YOLO txt | `class_id x_center y_center width height`（归一化坐标）|
| 位姿 txt | 目标星四元数 + 相对位置：`qx qy qz qw rx ry rz`（ECI 坐标系）|
| splits.json | train/val 拆分规则：每 5 帧取 1 帧为验证集 |

### 6.4 数据集拆分

按 **间隔采样** 拆分：每 5 帧取 1 帧为验证集，其余为训练集。

核心批 1810 帧：train = 1448, val = 362。

## 七、渲染分批策略

### 7.1 渲染范围

核心渲染批覆盖 t = 22482～24291 秒（距离 < 1000 km），共 1809 帧，分 4 批：

| 批次 | 帧段 | 距离 (km) | 帧数 | 说明 |
|------|------|-----------|------|------|
| 1 | 22482-22935 | 1000 → 500 | 454 | 接近段 |
| 2 | 22936-23389 | 500 → 47.8 | 454 | 快速接近 + 最近距离 |
| 3 | 23390-23843 | 47.8 → 500 | 454 | 远离段 |
| 4 | 23844-24291 | 500 → 1000 | 448 | 远离段 |

### 7.2 目标可见性

| 距离 | 目标像素 @2048 | 可见性 |
|------|---------------|--------|
| 1000 km | ~10 px | 小光点 |
| 500 km | ~20 px | 可辨认 |
| 250 km | ~40 px | 清晰 |
| 48 km | ~200 px | 部件可分辨 |

### 7.3 工作规范

1. **渲染输出按批次分类建文件夹**：`output/images/{start}_{end}_s64_r2048/`
2. **小批量验证后必须用户确认再跑大批量**：>100 帧的批次启动前先验证 ≤50 帧

## 八、关键踩坑记录

### 8.1 MATLAB 编码

- `.m` 文件必须纯 ASCII（英文注释）——GBK 环境的 MATLAB 无法正确读取 UTF-8 中文
- STK Connect 不接受中文路径——`.e` 文件临时写到 `tempdir`（ASCII）再加载
- `readmatrix` 需 R2019a+；旧版 MATLAB 用 `xlsread` 回退
- `jsonencode` 无 `'PrettyPrint'` 参数；`datetime` 需显式 `'Locale','en_US'`

### 8.2 STK API

- `stkSetPropClassical` 的 a 单位为**米**，角度单位为**弧度**（容易误用 km/deg）
- `stkPosVelCBI('Sun', t)` 不存在——Sun 不是 propagated vehicle
- `stkAttitudeCBI` 不可靠——改为几何计算（观察星指向目标 + 目标星对地定向）
- `stkObjNames()` 无参调用

### 8.3 Blender 5.2

- `bpy.ops.object.delete()` 无 `use_confirm` 参数
- `Material.use_nodes` 已弃用，材质节点需显式 `new()`
- **Track To 约束**在 `-b` 后台模式不生效 → 相机/太阳用旋转矩阵直接构造
- **物体 scale≠1 时 emission 材质不可见** → 用 `size=` 或 `transform_apply(scale=True)`
- **Denoising 抹除小目标** → 必须关闭
- **`Render Result` 渲染两次后 pixels 为空** → mask 用 EXR 写盘回读
- **World shader 图片纹理不可工作** → 星空用物理几何体替代
- **`images.new()` 无像素缓冲** → mask PNG 用 zlib/struct 手写
- PowerShell 调用需 `&` 前缀

### 8.4 坐标与尺度

- ECI 与 Blender 世界坐标 1:1 映射（均为右手系 Z-up）
- Blender 四元数顺序为 `(w, x, y, z)`，从 STK `(qx, qy, qz, qw)` 取时需注意
- 场景用 km 单位避免浮点精度问题

> 编写日期：2026-08-25
> 目标：将本机（MATLAB + STK 11.6 + Blender 5.2 渲染管线）完整迁移到内网机器，迁移后可独立复现：星历生成（MATLAB/STK）→ 渲染（Blender）→ 标注生成 → 数据集交付全流程。

## 三、打包方式

1. **压缩格式**：用 7-Zip（`.7z`，压缩率高）或 NTFS 直接对拷（移动硬盘）。注意：**不要用 FAT32 格式的移动硬盘**（单文件 4 GB 上限，数据集里有大文件），用 NTFS 或 exFAT。
2. **中文文件名**：`轨道2.xlsx`、`给钱室（公开）.xlsx` 等为中文名——拷贝后在内网机器上**保持文件名不变**（MATLAB 代码引用的是 `orbit_data.xlsx` 这个 ASCII 名，原始中文名文件仅供归档，不影响代码）。
3. **校验**：打包后生成 `sha256sum` 清单，到内网后逐包校验，避免静默损坏（渲染数据量大，一个字节错都会导致图像坏点）。
4. **分包建议**：按上表 4 个包分开压缩，避免单个超大压缩包传输中断后重来。

## 四、内网部署步骤

> 前提：内网机器为 Windows 10/11，有 NVIDIA GPU（建议 ≥8 GB 显存），磁盘空闲 ≥ 200 GB。

### 步骤 1：安装基础软件

```
1. 安装 NVIDIA 驱动（版本 ≥ 591.86 或内网批准版本）
2. 安装 MATLAB R2018b（用包 ② 的安装介质 + 离线许可激活）
3. 安装 STK 11.6（按 STK11.6详细安装教程v2.pdf）
   → 安装后将 STK_1160_complete_include_develop.lic 复制到
     C:\ProgramData\AGI\LicenseData\（覆盖或新增均可）
4. 解压 Blender 到 E:\Blender\（保持路径不变）
5. 安装 Python（与本机同版本），用包 ② 的离线 wheel 安装依赖
```

**强烈建议保持与本机相同的盘符布局**（项目根在 `F:\钱室\卫星图像仿真`、Blender 在 `E:\Blender`、数据集在 `E:\sat_dataset`）。以下文件里硬编码了这些路径：

| 文件 | 硬编码路径 |
|------|-----------|
| `tools\render_loop_v2.py` / `render_loop_v2_1.py` / `render_loop.py` | `BLENDER = "E:/Blender/blender.exe"`、`OUTPUT_BASE = "E:/sat_dataset/v2.x"` |
| `tools\gen_factors_csv.py` | `EPHEM_DIR`（相对项目，自动） |
| `tools\make_report_figures.py` | `ROOT = "E:/sat_dataset/v2.0"` |
| `blender\check_blend_load.py` | 一处硬编码 `F:\钱室\卫星图像仿真\...` |

若内网机器盘符不同，改这几处即可；路径一致则**零修改**。

### 步骤 2：部署项目

```
1. 将包 ① 解压到 F:\钱室\卫星图像仿真\
2. 确认以下文件齐全：
   - orbit_data.xlsx、轨道2.xlsx、给钱室（公开）.xlsx（项目根）
   - data\sat_models\ 下 135 个 .fbx + 纹理
   - output\blend_files\ 下 15 个 .blend
   - dataset\segB_v2\ephemeris\ 下 5 个文件
3. git status 确认工作区状态与打包前一致
4. 配置 git 本地仓库（内网无 GitHub）：
   git remote remove origin
   （或改为内网 GitLab 地址：git remote set-url origin <内网git地址>）
```

### 步骤 3：配置 MATLAB + STK 联调

```matlab
% MATLAB 内：
addpath('E:\STK_11.6\bin\Matlab')   % .m 包装函数
addpath('E:\STK_11.6\bin')          % .mexw64 二进制
% 两个目录都必须加，缺一不可

% 验证连接：
cd 'F:\钱室\卫星图像仿真\matlab'
test_stk_connection     % 应输出连接成功
```

> 注意：MATLAB R2018b 与 STK 11.6 的 COM 连接在本机有过多次踩坑记录（见 `CLAUDE.md` "STK 连接" 一节）：失败后要**任务管理器杀光 STK.exe / MATLAB.exe 进程再重试**，这是环境特性而非代码问题。

### 步骤 4：部署数据集（可选）

```
将包 ③ 的 v2.1 解压到 E:\sat_dataset\v2.1\
```

### 步骤 5：端到端验证

按以下顺序逐项验证，全部通过才算迁移成功：

| # | 验证项 | 命令/方法 | 预期结果 |

## 五、风险与注意事项

1. **STK 许可不绑机器**：当前许可是 `HOSTID=ANY` 永久节点许可，文件直接复制即可用，无需重新激活。但**许可文件属保密材料，按内网保密规定流转**。
2. **MATLAB 版本必须 R2018b**：代码用了旧版兼容写法（`xlsread` 回退、无 `readmatrix`），若内网机器装的是更新版本，需回归测试 `stk_helpers/loadOrbitExcel.m` 等函数。
3. **中文路径**：项目根目录含中文（`F:\钱室\卫星图像仿真`）。本项目的踩坑记录全部围绕"代码文件名用 ASCII、路径中文"的约定，迁移后保持同一目录名可避免新问题。
4. **Blender 绿色版拷贝**：Blender 5.2 是免安装版，直接拷目录即可；但**首次在内网机器运行时**要确认 GPU 设备识别（`Edit → Preferences → System → Cycles Render Devices` 应显示 NVIDIA RTX 系列）。若内网机器无 NVIDIA GPU 或驱动过旧，OptiX 渲染会退回 CPU，速度大幅下降。
5. **git 历史**：包 ① 打包时务必把 `docs\数据集使用手册.md` 提交进去（当前为未跟踪文件）。
6. **数据敏感性**：`轨道2.xlsx`（82 MB，非公开轨道数据）与 `给钱室（公开）.xlsx` 的敏感级别不同，迁移前按内网规定审批。

---

## 六、迁移完成后的工作建议

- 在内网机器建立本地 git 分支，后续开发在内网进行
- 将 `CLAUDE.md` 中的路径表更新为内网实际路径（若盘符有变）
- 若内网机器配置不同（如显存更大），可考虑提高 `--samples` 或 `SUB_BATCH_SIZE` 加速渲染

# 卫星模型渲染几何错误修复报告

> 日期：2026-08-04 | 相关提交：`21d503c`

## 问题描述

在 Blender Cycles 渲染卫星交会仿真图像时，目标卫星模型呈现严重的几何扭曲——太阳能翼板显示为交叉的薄片，卫星本体比例不对，整体呈现"薄片拼插"形状。该问题在手搭简易模型和 DSP 卫星模型上均存在，且在不同渲染距离下表现不一致。

## 排查历程

1. **怀疑 FBX 导入管线**：对比 `fbx_minimal.py`（已知正确）和 `render_scene.py`（有问题），发现 transform 处理有差异
2. **怀疑材质系统**：100% emission 无方向性光照可能掩盖几何问题
3. **怀疑姿态四元数**：`tgt_quat` 旋转可能导致面板侧对相机
4. **关键线索**：50m 近距离测试渲染几何正确，47.8 km 正式渲染几何错误——同样的模型、同样的材质、同样的姿态
5. **最终定位**：距离差异 → 场景绝对坐标 → 浮点精度

## 根因分析

### Bug 1：模型加载管线缺少 transform bake

**旧代码行为：**

- FBX 模型加载后，仅对顶层空节点设置 `scale = (KM_SCALE, KM_SCALE, KM_SCALE)`
- 子 mesh 对象从未调用 `transform_apply()`，残留非 identity 的 local transform
- Blender 5.2 已知 bug：物体 `scale ≠ 1` 时，emission 材质渲染异常，几何体可能部分不可见或变形
- 材质为 100% emission（`MixShader Fac = 1.0`），所有表面纯色自发光，立方体和平面看起来完全相同——无法分辨三维形状

**修复：**

1. 对每个 mesh 依次执行：unparent → `transform_apply(location=True, rotation=True, scale=True)` → 几何中心归零 → KM_SCALE 缩放
2. 所有 mesh 最终获得 identity transform（`location=0, rotation=0, scale=1`）
3. 材质改为 95% BSDF + 5% emission，方向性光照恢复三维深度感
4. 新增 `_bake_transform()`、`_unparent_meshes()`、`_center_and_scale_to_km()` 等函数统一处理流程

### Bug 2：浮点精度不足（真正的根因）

**为什么 Bug 1 修复后，50m 距离正确但 47.8 km 仍然错误？**

Blender 内部使用 **32 位浮点数（float32）** 进行顶点变换和渲染。float32 约 7 位有效数字。

仿真场景使用 ECI（地心惯性）坐标系，原点在地球中心。GEO 轨道上的观测星和目标星距原点约 **42,164 km**。

在此距离下，float32 的最小可分辨距离：

```
42,164 km ÷ 2²³ ≈ 0.005 km = 5 米
```

DSP 卫星模型最大尺寸仅 **6.3 米**。模型顶点坐标被截断到 5 米粒度，太阳能翼板（厚度 0.04 米）直接消失，本体被扭曲——这就是"薄片拼插"几何错误的根本原因。

**为什么 50m 测试正确？**

50m 处 float32 精度 = 50m ÷ 2²³ ≈ **0.006 mm**，远高于 6.3 米模型的需求。

**为什么 47.8 km 正式渲染也错误？**

47.8 km 是观测星到目标星的**相对距离**。两个星的**绝对 ECI 坐标**都约 42,164 km。旧管线将相机放在 `obs_pos`（~42,164 km），模型放在 `tgt_pos`（~42,164 km）。Blender 渲染时计算 `camera.matrix_world @ vertex_local_position`，该运算在 Blender 的 float32 中执行——精度损失发生在渲染管线的顶点变换阶段，而非数据准备阶段。

**修复：坐标平移**

将相机平移至场景原点，所有物体使用相对坐标：

```python
# 旧代码（错误）
camera.location = obs_pos       # ~42,164 km → float32 精度 ~5m
model.location  = tgt_pos       # ~42,164 km → float32 精度 ~5m

# 新代码（正确）
rel_tgt = tgt_pos - obs_pos     # Python float64 精确计算，精度 ~1e-12 km
camera.location = Vector((0, 0, 0))  # 原点，精度无限
model.location  = rel_tgt             # ~48 km → float32 精度 ~6mm ✓
earth.location  = -obs_pos            # ~42,164 km（球体，精度需求低）
```

关键：相机 `matrix_world` 不再包含 `Translation(obs_pos)`，仅保留旋转矩阵。

## 技术要点

### float32 精度速查表

| 距原点距离 | 最小可分辨尺寸 | 可渲染的最小目标 |
|-----------|---------------|-----------------|
| 1 m | 0.12 μm | 任意 |
| 1 km | 0.12 mm | 任意 |
| 100 km | 12 mm | 任意 |
| 1,000 km | 12 cm | > 0.5m 目标 |
| 10,000 km | 1.2 m | > 5m 目标 |
| 42,164 km (GEO) | **5 m** | > 20m 目标 |

### 验证方法

1. 在同一帧（frame 23386，距离 47.8 km）分别以 50m 人工距离和真实仿真距离渲染
2. 使用相同的模型、材质、相机参数
3. 50m 渲染正确 + 47.8 km 渲染错误 → 确认浮点精度为根因
4. 应用坐标平移修复后，两个距离均渲染正确

## 经验教训

1. **Blender 后台模式（-b）无法检查视觉结果**，需要先写小规模测试脚本验证，再跑大批量
2. **浮点精度问题隐蔽性极强**——近距离正确、远距离错误，容易误判为旋转或材质问题
3. **凡是涉及大坐标范围的场景**（地心坐标系、太阳系尺度等），必须将渲染目标放在原点附近
4. **Blender 5.2 有多个已知 bug**（见 CLAUDE.md），开发前应完整阅读踩坑记录

## 1. 项目概述

以观察卫星第一视角对目标卫星进行交会工况连续成像仿真，生成带像素级标注（检测/分割/位姿）的仿真图像数据集，用于空间目标感知算法验证。

**技术路线：** MATLAB 控制 STK 构建双星交会场景 → 导出 ECI 星历 CSV → Blender Cycles 批量渲染 2048×2048 图像 + 自动生成 COCO/YOLO/位姿标注。

**数据源：** `orbit_data.xlsx` — 34201 行瞬时轨道根数（1 秒/行），a 单位米，角度单位弧度。双星均为 GEO 轨道，观察星执行变轨机动，目标星保持稳定轨道。

**全工况距离剖面：** 16327 km → 47.8 km（最近交会）→ 11198 km，太阳相位角 40°–142°。

## 5. 数据流

### 5.1 MATLAB 阶段

```
1. config/scenario_config.m → config 结构体
2. +stk_helpers/initSTK.m → COM 启动 STK + Connect 连接
3. +stk_helpers/buildScenario.m → 创建场景：
   ├─ loadOrbitExcel.m ← orbit_data.xlsx
   │    └─ kepler2cart.m (34201 行 × 2 颗星)
   ├─ stkSetEphemerisCBI → 写入 .e 文件 → STK 加载星历
   ├─ 创建 EOIR 传感器（观察星）
   └─ 设置姿态（目标跟踪）
4. +stk_helpers/exportAllEphemeris.m → 导出：
   ├─ stkEphemerisCBI → 读回位置/速度
   ├─ computePointingQuaternion → 观察星指向四元数
   ├─ computeNadirQuaternion → 目标星对地四元数
   ├─ computeSunPositionECI → 太阳 ECI 位置（Meeus 算法）
   ├─ writeStateCSV → observer_state.csv, target_state.csv
   ├─ sun_state.csv, aux_data.csv
   └─ scene_config.json
```

### 5.2 Blender 阶段

```
render_scene.py (Blender -b 后台模式)
├─ load_all_data() → 读取 4 个 CSV + 1 个 JSON
├─ clear_scene() → 删除默认物体
├─ create_earth() → 地球球体 (r=6371 km, 8K 贴图)
├─ create_satellite_model() → 卫星模型：
│   ├─ 'dsp_blend' → 加载 DSP.blend (分离组件 + 完整模型)
│   ├─ 'auto'      → 自动检测可用的模型
│   └─ 'simple'    → Blender 几何体手搭模型
│   └─ 统一处理管线：
│       1. 删除非 mesh 对象
│       2. Unparent (CLEAR_KEEP_TRANSFORM)
│       3. Bake 全部 transform → identity
│       4. 几何中心归零
│       5. KM_SCALE × model_scale 缩放到 km
│       6. 分配 emission+BSDF 材质
├─ setup_camera() → 相机 (原点, FOV)
├─ setup_sun() → 方向光 (energy=60)
├─ setup_stars() → 星空背景板 (相机跟随)
├─ setup_render() → Cycles 配置
│
└─ 逐帧循环：
    ├─ update_frame() → ★ 相机在原点，所有坐标相对观测星
    │   ├─ rel_tgt = tgt_pos - obs_pos
    │   ├─ 相机 → 原点, 指向 rel_tgt
    │   ├─ 模型 → rel_tgt, quat = tgt_quat
    │   ├─ 地球 → -obs_pos
    │   └─ 太阳 → rel_sun 方向
    ├─ Beauty 渲染 → output/images/<tag>/frame_XXXX.png
    ├─ assign_mask_materials() → 纯色 emission
    ├─ Mask 渲染 → EXR → numpy → output/annotations/
    ├─ mask_to_annotations() → COCO + YOLO
    └─ write_pose_file() → 位姿真值
```

| 系统 | 说明 |

## 6. MATLAB 管线详解

### 6.1 main.m — 主入口

5 个阶段：加载配置 → 初始化 STK → 构建场景 → 导出星历 → 汇总。STK 在脚本完成后保持运行。

### 6.2 initSTK.m — 双模启动

先尝试 `actxGetRunningServer` 接管已有 STK 实例，否则 `actxserver` 启动新实例。然后 `stkOpen` + `stkInit` 建立 Connect 连接。

**关键约束：** COM 对象必须 `assignin('base', ...)` 防止被垃圾回收杀死 STK。

### 6.3 buildScenario.m — 场景构建

- 两种模式：`'excel'`（从 Excel 文件加载）和 `'manual'`（手动 Keplerian 轨道根数）
- Excel 模式：`loadOrbitExcel` → `stkSetEphemerisCBI`（写 .e + 加载 + 切换 StkExternal）
- 手动模式：`stkSetPropClassical`（14 参数，a 单位米，角度单位弧度）
- 传感器和姿态配置尝试通过 Connect 命令，失败则需 STK GUI 手动完成

### 6.4 exportAllEphemeris.m — 星历导出

输出 5 个文件，关键函数：

| 函数 | 功能 |
|------|------|
| `computePointingQuaternion()` | 观察星 Z 轴指向目标星，Y=轨道法向 |
| `computeNadirQuaternion()` | 目标星 Z 轴指向地心 |
| `computeSunPositionECI()` | Meeus 天文算法，无 STK 依赖 |
| `writeStateCSV()` | 位置 + 速度 + 四元数 → CSV |

### 6.5 kepler2cart.m — 轨道力学核心

输入：a(米), e, inc, RAAN, argp, nu(弧度)。输出：ECI r(3×1 米), v(3×1 米/秒)。算法：近焦点坐标系 → ECI 旋转矩阵。μ = 3.986004418×10¹⁴ m³/s²。

### 6.6 loadOrbitExcel.m — 数据加载

从 `orbit_data.xlsx` 读取 34201 行，每行调用 `kepler2cart` 计算两颗星的状态向量。自动检测并修复 4 行退化数据（e≈0 导致近地点幅角不稳定，用线性插值修复，误差 < 0.001 km）。

## 7. Blender 渲染管线详解

### 7.1 render_scene.py — CLI 参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `--ephem_dir` | (必填) | 星历 CSV 目录 |
| `--start` | 0 | 起始帧（0-based） |
| `--end` | all | 结束帧（不含） |
| `--stride` | 1 | 帧间隔 |
| `--samples` | 64 | Cycles 采样数 |
| `--resolution` | 2048 | 正方形分辨率 |
| `--tag` | auto | 输出子文件夹名 |
| `--camera_mode` | track | `track`（追踪）或 `stare`（固定指向） |
| `--fov` | 0.117 | 相机 FOV（度） |
| `--model_scale` | 1.0 | 模型缩放（如 10.0 = 10倍） |
| `--model_type` | auto | `auto`/`dsp_blend`/`simple` |
| `--no_annotations` | false | 跳过标注生成 |
| `--render_device` | gpu | `gpu`（OptiX 加速）/ `cpu` |

### 7.2 模型加载管线

**三种模型类型：**

| 类型 | 来源 | 部件数 | 说明 |
|------|------|--------|------|
| `dsp_blend` | `output/DSP.blend` | 1 完整+8 分离 | 用户手动标注面 + 剩余完整面 |
| `auto` | 自动检测 | 变 | 优先 DSP.blend，其次 FBX，最后 simple |
| `simple` | Blender 几何体 | 5 | body(4m) + 2 panels(4m×1m) + 2 antennas |

**统一处理管线（所有类型）：**
1. 删除非 mesh 对象（相机、灯光、空节点）
2. Unparent 所有 mesh（CLEAR_KEEP_TRANSFORM 保持世界位置）
3. Bake 全部 transform（`transform_apply(location, rotation, scale)`）
4. 几何中心归零
5. `KM_SCALE × model_scale` 缩放到 km
6. 分配 emission(85%) + BSDF(15%) 材质

**材质参数：**
- Emission Strength: 3.0（太空可见性）
- BSDF Roughness: 0.4, Metallic: 0.3
- Mix Fac: 0.85（85% 自发光 + 15% 方向光）

**Beauty/Mask 双模式：**
- Beauty 渲染：完整模型 + 标注面都可见
- Mask 渲染：隐藏完整模型，标注面显示纯色（pass_index 编码在红通道）

### 7.3 坐标系精度修复（关键）

**问题：** 卫星在距场景原点 ~42164 km 处。Blender 使用 32 位浮点数，在此距离精度仅 ~5 米。DSP 模型仅 6.3 米宽，顶点被截断导致几何扭曲。

**解决：** `update_frame()` 将相机放在原点，所有物体用相对坐标：
```python
rel_tgt = tgt_pos - obs_pos       # Python float64 精确计算
camera.location = (0, 0, 0)        # 相机在原点
model.location = rel_tgt           # 模型在 ~48 km，精度 ~6mm
earth.location = -obs_pos          # 地球相对位置
```

### 7.4 标注生成流程

每帧执行两个渲染 pass：

1. **Beauty pass**（64 samples）：正常 RGB 渲染
2. **Mask pass**（1 sample）：
   - 所有标注面材质替换为纯色 emission（红通道 = pass_index/255）
   - 完整模型设为隐藏
   - 渲染到临时 EXR → 读取为 numpy float32 数组 → 转为 uint8 mask
   - 用 zlib/struct 手写 PNG（绕过 Blender image API 已知 bug）

从 mask 中提取标注：

| 标注格式 | 内容 |
|----------|------|
| COCO Detection | image_id, category_id, bbox, area |
| COCO Segmentation | 同上 + RLE 编码 (column-major) |
| YOLO | class_id x_center y_center width height (归一化) |
| Pose | qx qy qz qw rx ry rz |

**标注类别：**

| ID | 名称 | 像素值范围 |
|----|------|-----------|
| 1 | body | 1 |
| 2 | solar_panel | 2–99 |
| 3 | phased_array_antenna | 100–149 |
| 4 | reflector_antenna | 150–199 |
| 5 | solar_panel_tripod | 200–249 |

## 11. 踩坑记录

### MATLAB 编码
- .m 文件必须纯 ASCII（中文 Windows MATLAB GBK 环境，UTF-8 中文必乱码）
- STK Connect 不接受中文路径 → `.e` 文件写入 `tempdir`（ASCII 安全）
- Excel 文件名引用必须 ASCII

### MATLAB 兼容性（< R2019a）
- 无 `readmatrix` → 用 `xlsread` 回退
- `jsonencode` 不支持 `PrettyPrint`
- `datetime` 需显式 `'Locale', 'en_US'`
- 包（+package）内函数互调需 `stk_helpers.func` 前缀

### STK 连接
- COM 启动 + Connect API 混合模式最稳定
- 纯 TCP Connect 不稳定（连接池被占满）
- 失败后杀光 STK.exe/MATLAB.exe 再重试
- `stkOpen` 只能连已运行的 STK
- COM 对象必须 `assignin('base', ...)` 防被回收

### STK API
- `stkSetPropClassical`: a 单位米，角度单位弧度，14 参数
- `stkAttitudeCBI` 不可靠 → 四元数由位置/速度几何计算
- `stkPosVelCBI('Sun', t)` 不存在 → Sun 用 Meeus 算法
- `stkObjNames()` 无参调用

### Blender FBX 导入
- 删除 FBX 自带的相机/灯光/空节点
- 清除 FBX 材质后重新分配
- **必须 Bake 所有 transform**（`transform_apply(location, rotation, scale)`）
- scale≠1 + emission = 渲染不可见

### Blender 5.2
- `bpy.ops.object.delete()` 无 `use_confirm`
- `Material.use_nodes = True` 已弃用 → 节点显式 `new()`
- Track To 约束在 `-b` 模式不生效 → 用旋转矩阵
- Denoising 会抹掉 30px 小目标 → `use_denoising = False`
- `Render Result` 第二次渲染后像素为空 → mask 用 EXR write+read
- `bpy.data.images.new()` 像素为空 → mask PNG 用 zlib/struct 手写

### 场景尺度
- Blender 统一 km（m × 0.001）
- 相机 clip: 0.01–200000 km
- ECI(J2000) 与 Blender 右手 Z-up 1:1 映射

### 浮点精度
- 物体在距原点 ~42164 km 处时，float32 精度仅 ~5m
- **解决：相机放原点，所有物体用相对坐标**

## 13. 数据扩增系统（Phase 1-2）

### 姿态扩增（Phase 1）

每帧渲染时对目标卫星施加随机姿态扰动，增加视角多样性。

| CLI 参数 | 默认值 | 说明 |
|----------|--------|------|
| `--frame_variations` | 1 | 每帧变体数量 |
| `--attitude_jitter_deg` | 0 | 随机扰动最大角度（度） |

**原理：** 在 `update_frame` 中注入均匀锥形分布的随机轴角旋转。扰动后的姿态写入 pose 文件。v000 = 原始姿态，v001-vNNN = 扰动变体。

### 光照变化（Phase 2）

在渲染端旋转太阳方向，模拟顺光/侧光/逆光等不同光照条件。太阳绕相机-目标-太阳平面法向量旋转，最大化光照变化。

| CLI 参数 | 默认值 | 说明 |
|----------|--------|------|
| `--sun_phase_offsets` | 空 | 逗号分隔的偏移角度，如 `"60,120,180"` |
| `--sun_energy_range` | 空 | 太阳能量随机范围，如 `"100,300"` |

**材质：** 95% BSDF + 5% 自发光，接近真实太空光影——受光面明亮、背光面阴暗。

### 组合使用

```powershell
blender -b -P blender/render_scene.py -- \
  --frame_variations 10 --attitude_jitter_deg 90 \
  --sun_phase_offsets "60,120,180" \
  --tag "aug_combo" ...
```

每帧产生 10 姿态 × 4 光照 = 40 变体。444 帧 segB → 17,760 张。

## 14. 点目标数据集生成（Phase 4）

分析式生成器 `tools/point_target_generator.py`，无 Blender 依赖。

**原理：**
1. 相机投影：从 ECI 星历计算亚像素坐标
2. 高斯 PSF 合成：σ=1.2 形成 2-3 px 可见斑点
3. 恒星星场：10000 颗幂律分布随机恒星
4. 传感器噪声：高斯 σ=3.0

**CLI 参数：**

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `--fov` | 14.0 | 视场角（度） |
| `--camera_mode` | stare | track/stare |
| `--psf_sigma` | 0.7 | PSF 标准差 |
| `--bg_noise_std` | 3.0 | 噪声标准差 |
| `--resolution` | 2048 | 图像分辨率 |

**输出：** 8-bit 灰度 PNG + `labels.csv`（frame_id, cx_px, cy_px, brightness, dist_km, sun_phase_deg）

```bash
python tools/point_target_generator.py \
  --ephem_dir output/ephemeris \
  --output_dir output/dataset_point --tag "batch_001" \
  --start 22482 --end 23166 --stride 25 --fov 14 --camera_mode stare
```

## 15. 数据集打包（Phase 5）

`tools/dataset_builder.py` 将分散的渲染批次整合为统一数据集（索引模式，不复制文件）。

**两种模式：**

| 模式 | 输入 | 输出 |
|------|------|------|
| `--mode point` | 点目标生成器输出 + segA/C 渲染图 | `labels.csv` + `manifest.json` + `splits.json` |
| `--mode close` | segB 渲染图 + COCO JSON | `instances.json`（COCO）+ `manifest.json` + `splits.json` |

```bash
# 数据集 A（点目标）
python tools/dataset_builder.py --mode point \
  --source "dir1,dir2,..." --output dataset_point/v1

# 数据集 B（检测/分割）
python tools/dataset_builder.py --mode close \
  --source "dir1,dir2,..." --output dataset_close/v1
```
